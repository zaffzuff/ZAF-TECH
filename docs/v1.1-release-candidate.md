# ZAF TECH v1.1 Release Candidate

## Implemented

- Unified Observation Engine with shared observation data and explicit freshness states.
- Observation freshness state: fresh, aging, stale, unknown.
- Observation confidence score with explicit evidence reasons.
- Observation health indicators with network, ecosystem and freshness components.
- Optional historical observation storage through DATABASE_URL.
- Public observation reads are separated from protected snapshot persistence.
- App Health reads use stored observations; expensive health collection is isolated behind the protected scheduler path.
- App Health URL checks include SSRF-oriented hostname/IP validation, timeout and redirect controls.
- DeFi public reads are read-only; snapshot persistence is isolated behind a protected scheduler endpoint.
- Ecosystem snapshots can record newly observed official Pi Network blog items as explicit ecosystem changes.
- Unified legacy /api/zaf and /api/zaf/ecosystem routes.
- Network Deep View and validated ledger lookup endpoint.
- Confidence-aware Radar endpoint.
- Global Search endpoint and /search page.
- Observatory 2.0 at /observatory.
- Node Health Score engine and /node-health page.
- Wallet Activity Analytics engine and /wallet-observatory page.
- Wallet API analytics fields remain public/read-only.
- Public API responses use bounded limits, cache policies and best-effort request rate limiting where expensive inputs are exposed.
- Runtime error, loading and not-found boundaries are present.
- Nine-language UI scope: English, Turkish, Spanish, Chinese, Italian, French, German, Portuguese and Russian.
- Locale-safe layout containment rules are in place for long translated labels and externally sourced identifiers.
- Node → Compute Connector user guidance is included in the application.
- Regression checks are enforced in CI.
- Pi integration boundary is defined, but Pi SDK, authentication and payments remain disabled.
- Application version is 1.1.0.

## Boundaries

- No private wallet credentials are requested or stored.
- Node health is descriptive for the local Connector observation.
- Network values describe observed samples and are not complete calendar-day totals unless explicitly stated.
- Ecosystem source availability is not the same as content verification.
- Historical storage remains optional when DATABASE_URL is absent.
- In-memory API rate limiting is best-effort and is not a distributed security control.
- Public observation endpoints do not trigger snapshot persistence or force-refresh operations.
- Vercel Hobby currently runs the configured App Health scheduler daily; protected DeFi and observation scheduler endpoints can be triggered by an external scheduler or a future plan with higher cron frequency.
- Pi Authentication, Pi Payments and other Pi SDK capabilities are not enabled until the foundation freeze and explicit testnet verification are complete.
