# Pi identity verification boundary

Reviewed October 19, 2026. ZAF Tech is public, free and read-only. Pi sign-in now creates an encrypted 30-minute ZAF Tech session from the appropriate server-verified identity (App Studio for SDK, Pi Platform for web OAuth). Public read-only APIs remain public. Never use sessionStorage names as authorization. No payments, wallet scopes or extra login providers are introduced.

- Native Pi Browser / Pi Desktop (pi-node) in a parent shell: official SDK in the document head; await init({ version: "2.0" }) without a sandbox override, then native username auth and App Studio verification. Direct top-level Pi Browser entries must open the fixed registered Pi app https://zaftechpu0455.pinet.com rather than start an unbridged consent promise. PiNet web host (pi-net) and ordinary browsers use the existing official web OAuth callback. The portal SDK-exclusive declaration still needs final review rather than an assumed exemption.
- SDK load/init/authentication timeouts: operations have deadlines. A rejected init may retry; a non-settling init/permission prompt needs a fresh document via **Reload and retry**. The SDK has no assumed cancellation API. No second initialization is started over an unknown in-flight operation. Late credentials cannot win after timeout/unmount. Both responsive headers share a synchronous busy lock.
- Token verification: one server-side POST to https://backend.appstudio-u7cm9zhmha0ruwv8.piappengine.com/pi/auth/v1/login with JSON { accessToken }, no-store, redirect rejection and a 10-second deadline. Validate sessionToken and bounded uid/username from that response only. Native SDK verification never falls back to Platform /me. Neither token is persisted or returned. Log only error classes.
- Own session: AES-256-GCM cookie __Host-zaf-pi-session-v2, fresh random IV, 30-minute absolute expiry, HttpOnly, Secure, SameSite=None, Partitioned and Path=/. ZAF_PI_SESSION_SECRET is a server-only 32-byte hex key in Vercel. GET /api/zaf/pi/session reads the authenticated cookie; same-origin DELETE clears it. Legacy cookies are ignored and expired on login/logout, requiring one new sign-in. Distinct names prevent partitioned/unpartitioned shadowing. Logout clears this browser cookie; copied cookies remain valid until expiry. No global revocation store is introduced.
- CSP: explicit connect-src allows self, socialchain.app (SDK internal verification), and the existing local Node Connector at http://127.0.0.1:39100. App Studio is not a browser connection. Restricted Pi frame ancestors and the exact production App Studio shell origin are allowed; no X-Frame-Options is emitted. Existing Next.js inline scripts are unchanged; this is not a complete script-src hardening project.
- Verifier requests: same-origin Origin required (the app's origin, not its Pi embedding ancestor), application/json, 8 KiB streamed body limit, 5-second body deadline, token max 4096 printable ASCII characters. No cross-origin or origin-less API client is supported by this browser-only endpoint.
- IP rate limit: 12/minute, database-backed when available. During database outage, per-instance local limiting preserves availability; it is not a distributed/global abuse guarantee. Proxy IP header integrity depends on the hosting platform. Pi upstream 429 is propagated with a validated Retry-After bounded to 1–300 seconds.
- Display and cookie reconciliation: username + verification timestamp only in sessionStorage. Both headers share a deduplicated GET /api/zaf/pi/session on mount, every 30 seconds and pageshow. Only a current server cookie confirms live verification; accessible but absent cookies clear display, temporary request failure downgrades it to Previously verified. Blocked embedded iOS storage preserves only historical display and offers Resume session. A revision/busy guard prevents stale responses from overwriting newer login/logout. The server retains its absolute 30-minute expiry; polling does not renew that cookie. Browser display data is never authorization. Both native and web exchanges require a matching cookie readback before showing success; logout requires a successful null readback.
- Web OAuth verification: `/signin/callback` posts only to `/api/zaf/pi/oauth`; the server calls the fixed official `https://api.minepi.com/v2/me` with Bearer authorization, no redirects/cache and a 10-second deadline. Same-origin/body/rate/session protections match native auth. Only the top-level validated uid/username from Pi Platform are trusted. OAuth UIDs are SHA-256 namespaced (`pi-oauth:`) in the encrypted session, separate from App Studio UIDs; usernames never link accounts. No access token is stored. Developer Portal OAuth and App Studio SDK registrations are distinct; do not send OAuth tokens to the App Studio login endpoint.
- OAuth: 24 random bytes of state, consumed once, local 10-minute age limit, reject future/missing age, mismatched/replayed/duplicate state and duplicate credential fields. Clear fragment before storage access. Preserve safe internal return path. No client secret or unsupported code/PKCE flow is invented.
- Browser storage failure must not turn a successfully verified native name into an authorization promise. Sign out removes the ZAF Tech cookie and display only; Pi global account consent/session remains managed by Pi.

## Embedded iPhone session follow-up

Owner identified iOS 16.7.16: canonical sign-in succeeded but identity disappeared before one minute and after reload. This matches the first 30-second session reconciliation, not the 30-minute expiry. iOS 16 lacks CHIPS; adding Partitioned alone cannot fix this device. GET /api/zaf/pi/storage tests actual HttpOnly cookie transport using a constant, identity-free 5-minute marker. On blocked iOS, requestStorageAccess is invoked directly from the user's click before any await. A fixed same-origin /signin/storage first-party page requires an actual POST interaction, seeds a nonidentity 30-minute visit cookie, and returns only to the fixed canonical PiNet URL. It rejects foreign Origin, disallows embedding/scripts, and never receives Pi credentials. No setting disabling tracking protection is required.

On iOS 16 a full page reload resets per-page storage access. Resume session requests access again; a remembered grant can avoid another prompt, but still requires a tap. Existing valid server sessions restore without repeated Pi consent. Denied permission remains denied without loops. Signout establishes cookie access first, including immediate clicks before the initial probe, then requires DELETE and null readback. Native/App Studio tokens and own session credentials never enter JavaScript storage. Physical same-Pi-Browser bootstrap → permission → login → 60 seconds → reload/Resume → signout/relogin remains required before claiming the iPhone issue resolved.
